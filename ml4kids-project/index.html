4프로젝트 공통 조건

모두 같은 조건으로 평가받기 위한 약속이에요.

  • 클래스(또는 예측 목표)는 2개 이상
  • 클래스별 학습 데이터 개수와 구성을 기록 (클래스당 8개 이상 권장, 클래스끼리 개수를 비슷하게)
  • 학습에 쓰지 않은 테스트 사례를 따로 준비 (4개 이상)
  • 실제로 틀린 예측(오분류)을 2건 이상 확인
  • 원인을 분석하고 1회 이상 개선, 개선 전·후는 같은 테스트 사례로 비교
  • 모델의 예측 결과로 실제 동작하는 Scratch 프로그램 제작
  • 교사 또는 친구에게 피드백 1회 이상 받고, 반영했는지와 그 이유를 기록
  • 프로젝트의 한계와 사회적 영향을 내 데이터·모델을 근거로 분석

29차시 · 마무리

정리 · 제출 · 현장 서술

모든 학생이 같은 시간을 씁니다
  • 앞 시간에 못 끝낸 단계를 마무리했다
  • 내 데이터·모델을 근거로 한계와 사회적 영향을 5문장 이상 분석했다 (데이터 편향, 특정 사용자 성능 저하, 오분류 피해, 공정성, 개인정보 등) 활동지 6

  • 마지막 10~12분, 인터넷·생성형 AI를 끄고 그날 받은 문항에 현장 서술을 썼다 활동지 9

일찍 끝낸 학생은 친구 프로젝트에 피드백을 남기거나 발표를 준비해요(성적 미반영). 결석한 학생은 따로 응시 기회를 받아요.

6생성형 AI 활용 유의사항

  1. 수행평가 이전에 생성형 AI는 프로젝트 주제 탐색, 데이터 구성 아이디어에 활용할 수 있다.
  2. 생성형 AI를 활용한 경우 사용한 AI 종류, 활용 목적, 실제 프로젝트에 반영한 내용을 활동지에 기록해야 한다.
  3. 최종 데이터 선정, 모델 학습, 테스트, 오분류 확인, 개선 전·후 비교, 프로그램 실행 확인은 학생이 직접 수행해야 한다. (생성형 AI 사용금지)
  4. 생성형 AI가 제시한 데이터, 코드, 성능 수치, 오분류 사례, 개선 결과를 실제 실행·검증 없이 그대로 제출한 경우 해당 내용은 감점될 수 있다.
  5. 수행평가 시간에 생성형 AI·인터넷 사용을 중단하고, 자신의 프로젝트 화면과 활동지를 바탕으로 직접 작성한다.

AI 입력창에 이름, 학번, 연락처, 다른 사람 사진 같은 개인 정보를 넣지 않아요. 제출한 내용이 실제 결과와 다르면 선생님이 설명을 요청할 수 있어요.
